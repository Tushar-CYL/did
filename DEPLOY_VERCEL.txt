WHAT GETS DEPLOYED
------------------
The website is the Next.js app in  webapp\ . Vercel builds it on
its own server and hosts the finished static site (plain
HTML/CSS/JS + data.json). No Python, no server, no database runs
on Vercel.

Everything Vercel needs is committed in the repo:

    vercel.json                 build recipe (build + output folder)
    webapp/package.json         the app + its exact pinned versions
    webapp/package-lock.json    so Vercel installs those same versions
    webapp/public/data.json     the numbers the live site shows
    webapp/app, components, lib the pages themselves

The Python scraper (app.py, src\) is NOT deployed - it keeps
running on the laptop and writes webapp\public\data.json.

---------------------------------------------------------------
 2. VERCEL - DONE (project linked to the repo)
---------------------------------------------------------------
The project  ey-account-intelligence  in the team "tushar's
projects" is connected to GitHub repo  Tushar-CYL/did , branch
main, with these settings (all of them matter):

    Framework Preset      : Other          (NOT "Python"/"Next.js")
    Root Directory        : EMPTY / default
    Build Command         : npm --prefix webapp run build
    Install Command       : npm --prefix webapp ci --no-audit --no-fund
    Output Directory      : webapp/out
    Environment Variables : none

Only the first two lines are unusual, and they are required
because this repo is a Python project with a Next.js site inside
webapp\: Vercel would otherwise detect "Python" from
requirements.txt, try to run app.py as a serverless function and
fail with PYTHON_ENTRYPOINT_NOT_FOUND. The same commands are ALSO
written in  vercel.json  at the repo root, so a re-import from
GitHub picks them up automatically.

Never add a variable such as NODE_ENV=production in the Vercel
dashboard: npm would then skip the dev-only build tools
(TypeScript, Tailwind) and the build fails. The site needs no
environment variables at all.

Never set Root Directory to "webapp". The committed vercel.json
already builds inside webapp\ and publishes webapp\out; changing
the root as well makes the paths point in the wrong place.

To re-create the project from scratch (only if it was deleted):
 1. Open https://vercel.com/new and sign in with GitHub.
 2. Import  Tushar-CYL/did .
 3. Set Framework Preset to  Other  (click it - do not accept a
    detected framework) and leave Root Directory empty.
 4. Leave Build/Output/Environment empty and click Deploy.
 5. Wait ~2 minutes for the first production deployment.


---------------------------------------------------------------
 3. FROM NOW ON: EVERY PUSH DEPLOYS ITSELF
---------------------------------------------------------------
Push a commit to the main branch and Vercel rebuilds + swaps the
live site in about 2 minutes. No button to press.

    git push origin main    -> production deploy (same URL)
    a pull request          -> separate preview URL (safe to test)

The monthly refresh is therefore just:

    python app.py                              (refresh the data)
    git add webapp/public/data.json
    git commit -m "data refresh"
    git push origin main

...and the live site shows the new numbers when Vercel finishes.
Faster: double-click  PUBLISH_SITE.bat  and pick an option; it runs
the right commands for you.

You do NOT need to run "npm run build" to update the numbers -
Vercel builds the site itself every time.

 4. WHAT LIVES WHERE
---------------------------------------------------------------
    vercel.json              build recipe Vercel reads   (COMMITTED)
    webapp                   the site source             (COMMITTED)
    webapp/public/data.json  what the live site shows    (COMMITTED)
    webapp/out               the built site - local only, never
                             committed (Vercel builds its own)

Vercel can only see committed files, so a data refresh goes live
only after data.json is committed and pushed.


---------------------------------------------------------------
 5. IF SOMETHING GOES WRONG
---------------------------------------------------------------
"PYTHON_ENTRYPOINT_NOT_FOUND" / "Found app.py but it does not
export a top-level app, application or handler"
    The project is using the Python framework preset. Vercel ->
    Project -> Settings -> Build & Development Settings ->
    Framework Preset -> change to  Other  and save, then
    Deployments -> Redeploy.

"No framework was detected" / build fails immediately
    vercel.json is not at the repo root, or Root Directory was
    changed. Commit vercel.json and keep Root Directory empty.

Build fails with a TypeScript, module or "next build" error
    Run the same build locally first, from this folder:
        npm --prefix webapp ci --no-audit --no-fund
        npm --prefix webapp run build
    Fix what it prints, push again - Vercel runs those exact two
    commands (see the "installCommand"/"buildCommand" in
    vercel.json).

Site builds but shows "Could not load data.json"
    webapp\public\data.json is missing from the repo. Commit it.

Site works but shows old numbers
    data.json was not committed. That file is the ONLY thing that
    updates the numbers:
        git add webapp/public/data.json
        git commit -m "data refresh"
        git push origin main

Pushed but Vercel did not rebuild
    Check Vercel -> Deployments. If nothing is there, the GitHub
    connection was lost: Project -> Settings -> Git -> reconnect
    Tushar-CYL/did (branch main), then push again.

/deep-dive opens a 404
    Keep trailingSlash: true in webapp\next.config.js (it is set)
    and use the URL with the trailing slash:  /deep-dive/

"Cannot find module './NNN.js'" or echarts errors
    Someone ran "npm audit fix --force" and broke the pinned
    versions. Restore them - in a Command Prompt:
        cd webapp
        git checkout package.json package-lock.json
        rd /s /q node_modules .next .next-dev
        npm install
    In PowerShell the same delete is:
        cd webapp
        git checkout package.json package-lock.json
        Remove-Item -Recurse -Force node_modules,.next,.next-dev
        npm install
    (DEPLOY_AZURE.txt section A3 explains why.)

Redeploy without changing code
    Vercel dashboard -> Deployments -> "..." -> Redeploy.

Roll back to an earlier version
    Vercel dashboard -> Deployments -> pick the old one ->
    "Promote to Production".


---------------------------------------------------------------
 6. OPTIONAL - DOMAIN AND ACCESS
---------------------------------------------------------------
    Dashboard -> Project -> Settings -> Domains  to attach a
    domain you own, or just keep the free *.vercel.app address.

    Deployment Protection (Settings -> Deployment Protection) can
    put a Vercel login in front of the site if it must stay
    internal. Without it the URL is public to anyone who has it.

    VISIBILITY CHECK: the GitHub repo Tushar-CYL/did is currently
    PUBLIC, which means the code, the .txt notes and
    webapp/public/data.json can be read by anyone on github.com,
    and the *.vercel.app link is open too. If this is internal EY
    material, do both of these:
       1. GitHub repo -> Settings -> scroll to "Danger Zone" ->
          "Change repository visibility" -> Private. Vercel can
          still deploy a private repo you own (free plan included).
       2. Vercel -> Project -> Settings -> Deployment Protection ->
          Vercel Authentication (or Password Protection on a paid
          plan if an outside person must open it).
    Note that making the repo private does not remove copies that
    were already downloaded/forked while it was public.
